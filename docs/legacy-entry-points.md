# Legacy entry-point inventory

This source inventory records which old widget and bot paths remain reachable
alongside the calendar product, what they can do, and which contract owns their
disposition. It distinguishes a configured capability from a concrete call
site: capability declarations alone do not establish a vulnerability.

| Surface                                                   | Reachability and guard                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Effects or returned data                                                                                                                                                                                                                                                                                  | Disposition                                                                                                                                                                                                                                                                              |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Calendar widget bootstrap and server gateway              | `AppContainer` requests a Matrix OpenID assertion and constructs `GatewayCalendarRepository`. Routes are `GET /v1/calendar/context`; `GET`, `POST`, `PATCH`, and `DELETE /v1/calendar/calendars`; `GET /v1/calendar/calendars/diagnostics`; `PATCH /v1/calendar/calendars/description` and `/color`; `GET`, `POST`, `PATCH`, and `DELETE /v1/calendar/events`; and `GET /v1/calendar/event`. `CalendarGatewayController` applies `MatrixAuthGuard` and `MatrixRoomMembershipGuard`; room services also resolve the configured binding and action authorization.                                                                                                                                                                  | Personal and bound-room calendar access through CalDAV. Room access and event writes remain independently default-off.                                                                                                                                                                                    | Supported. Keep OpenID identity, membership, power, binding, conditional writes, and calendar gates.                                                                                                                                                                                     |
| Widget capability declarations and store startup          | `main.tsx` passes capabilities for navigation, directory search, any-room timelines, sending member state, receiving room state and reactions, and sending/receiving every inherited `RoomEvents` type. `AppContainer` still mounts `StoreProvider`, whose initialization subscribes to legacy meeting event feeds.                                                                                                                                                                                                                                                                                                                                                                                                              | `StoreProvider` subscribes to store changes and calls `acceptMeetingInvitations`; that helper sends an `m.room.member` state event with `membership: join` for a matching invitation to a meeting created by the current user. | `!calendar` bot fallback                                  | `CommandController` receives room messages. `CommandService` routes `!calendar` before its legacy `!meeting` path; it checks that replying is safe for the room, applies a per-room/sender limiter, and delegates to `CalendarCommandService`, which resolves the room binding, room access/write gates, and action authorization.                                                                                                                                                                                                                                                                                                                                                                                               | Calendar reads and the explicitly supported command writes; safe Matrix replies.                                                                                                                                                                                                                          | Supported. | Room reminder configuration and alarm-options HTTP routes | `/v1/calendar/rooms/:roomId/reminders` (`GET`, `PUT`, `DELETE`) and `/options` use both Matrix guards. Configuration, room access, and delivery remain separate; defaults are off.                                                                                                                                                                           |
| Legacy meeting HTTP API                                   | `/v1/meeting/create`, `/update`, `/close`, and `/:roomId/sharingInformation` are registered on `MeetingController`. Before this change the membership guard read only a path or query `roomId`; it permits requests with no such value. `create` accepts `parent_room_id` from JSON and the service reaches bot-backed room creation.                                                                                                                                                                                                                                                                                                                                                                                            | A valid OpenID caller could supply a body-only parent room and reach the legacy room-creation handler without membership checked for that parent. The other routes are legacy meeting mutations or sharing lookup.                                                                                        | Disabled by ADR042: the first controller guard returns generic 404 for every HTTP request before membership lookup or service invocation.                                                                                                                                                |
| Legacy Matrix meeting RPC events                          | `MatrixServer` includes inherited `net.nordeck.meetings` event types in its sync filter and sets `userContext.userId` from the Matrix event sender. `MeetingController` handlers cover create, breakout, update, permission, close, participant, widget, and message events. The pilot guard denies RPC before handler invocation.                                                                                                                                                                                                                                                                                                                                                                                               | These handlers can create meeting rooms or change meeting state if invoked; their old behavior is unreachable through the pilot server controller.                                                                                                                                                        | Disabled by ADR042 for the pilot over both HTTP and RPC. Keep implementation for rollback and later retirement, but no legacy meeting controller event may reach its service or Matrix writes. #277 owns removal. This audit does not claim a permission model for the retired surface.  |
| Legacy `!meeting` and bot-addressed commands              | `CommandService` recognizes `!meeting` and the bot user ID after the `!calendar` branch. `ENABLE_WELCOME_WORKFLOW` gates the handler and defaults to `false`. Legacy commands remain available only with that explicit opt-in. If the legacy workflow is explicitly enabled, `setup` returns a localized disabled response without calling the meeting service; with the default-off gate, legacy commands are ignored.                                                                                                                                                                                                                                                                                                          | Legacy help, language, status, and replies remain available only with the legacy workflow opt-in. The `setup` command no longer changes widget or layout state. Its welcome-room marker is mutable: the SDK's `trusted_private_chat` preset gives invitees the creator's power.                           | Disabled by default with the legacy workflow gate. Setup always fails closed because the marker cannot prove who authorized a write to the original room; help no longer advertises it. `!calendar` is handled before the legacy gate and remains supported. #277 owns later retirement. |
| Welcome workflow and guest-member event controllers       | `WelcomeWorkflowController` receives Matrix invite, power-level, and member events; workflow operations return early when `enable_welcome_workflow` is false (the default). When enabled, the `room.invite` event sender triggers a private help-room flow and is the same user invited to that helper room; the workflow adds no separate source-room authorization check. With the workflow disabled, the existing `AutojoinRoomsMixin` joins ordinary bot invites. A power-level event can auto-add the widget only when bot widget power increases and the bot currently has widget-state power. `GuestMemberController` receives member and power-level events; guest power changes are separately gated and default false. | Matrix joins, welcome-room creation/invites, welcome-room state/messages, and conditional widget state changes when enabled; guest power changes only under their explicit gate.                                                                                                                          | The help-room flow is off by default. Its trigger and recipient are the delivered Matrix invite event sender; #277 owns later retirement. No blanket controller removal in #259.                                                                                                         |
| RPC error-room notifications                              | `WebExceptionFilter` catches RPC event-processing errors from command, welcome, guest, and meeting controllers. When `ENABLE_PRIVATE_ROOM_ERROR_SENDING` is true, it creates or reuses a private error room for `event.sender` (copied to `userContext.userId` by `MatrixServer`); this setting now defaults to `false`.                                                                                                                                                                                                                                                                                                                                                                                                         | With explicit legacy opt-in, an RPC error can create a private room and send the sender an error reference. When off, the failure reaction still runs without creating the room.                                                                                                                          | Legacy private error-room creation is off by default; the existing environment variable remains an explicit compatibility opt-in. #277 owns later retirement. Targeted config and filter tests cover the default.                                                                        |
| Matrix SDK autojoin and control-room migration            | `AutojoinUpgradedRoomsMixin` always listens for archived rooms and joins a replacement room. `AutojoinRoomsMixin` is installed when the welcome workflow is disabled, so that setting also changes invite handling. Control-room migration runs only when `enable_control_room_migration` is true (default false).                                                                                                                                                                                                                                                                                                                                                                                                               | Possible Matrix joins; optional control-room migration.                                                                                                                                                                                                                                                   | Retained and explicitly inventoried. The default-off welcome workflow installs the existing broad autojoin mixin, preserving ordinary invite joins. Migration remains default-off.                                                                                                       |
| Legacy configuration and widget-list HTTP reads           | `/v1/config` is protected by `MatrixAuthGuard` and returns homeserver/Jitsi/meeting-link configuration fields. `/v1/widget/list` has no Matrix guard and returns configured widget IDs, rendered names, and optional flags.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Read-only configured values; no Matrix or CalDAV write. The widget list is public in the current code.                                                                                                                                                                                                    | Retained as read-only legacy support; this audit found no side-effecting behavior in either handler. Revisit when the old widget UI is retired under #276.                                                                                                                               |
| Health HTTP endpoint                                      | `/v1/health` has no Matrix guard and performs a GET to the configured homeserver `/health` endpoint.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Public operational health result and one outbound homeserver health request per call.                                                                                                                                                                                                                     | Retained as an operational health endpoint, not a calendar or meeting command.                                                                                                                                                                                                           |
| Reminder background scheduler                             | Runtime starts with the server but schedules work only when room access, reminder delivery, the PostgreSQL store, principal credentials, and service URLs are all available.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Bounded CalDAV and Matrix reminder work when every independent prerequisite is enabled.                                                                                                                                                                                                                   | Supported and default-off. No scheduled reminder send occurs from the default configuration.                                                                                                                                                                                             |

Legacy meeting HTTP and RPC denial is covered by
`matrix-calendar-server/src/controller/MeetingController.contract.test.ts`.
HTTP create, update, close, and sharing-information requests return 404 before
membership lookup or meeting-service calls. The test also runs every registered
legacy RPC handler through Nest's guard consumer and proves none reaches a
service call. The legacy `!meeting setup` command contract is covered by
`matrix-calendar-server/test/CommandService.test.ts`: it returns a localized
disabled response without invoking the meeting service, and help no longer
advertises the command. The adjacent calendar gateway and `!calendar` contract
tests continue to cover supported paths.

The legacy private-room defaults and preserved invite join are covered by
`matrix-calendar-server/src/configuration.test.ts`,
`matrix-calendar-server/src/filter/WebExceptionFilter.contract.test.ts`,
`matrix-calendar-server/src/matrix/mixins/AutojoinRoomsMixin.test.ts`, and
`matrix-calendar-server/test/WelcomeWorkflowService.test.ts`.
